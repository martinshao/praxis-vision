# 摄影技能资产库方案

- Scope：INIT；对应 PRD v3；2026-09-15。
- 用户请求：根据指定文章分析如何将摄影方法固化为类似 skill 的资产库。
- 文章：[南鸢的机位拆解文章](https://x.com/nanyuan0412/status/2099683245726355869)。已通过浏览器阅读正文；搜索工具访问返回 403。
- 本文技能结构、交互与首版范围是产品建议，不是作者提供的现成 Skill，也不是已验证生图能力。

## 从文章提炼的方向

文章以画面意图为起点，将机位的不同因素拆开，并提醒不要把距离、焦段与最终取景效果混为一谈。对工作台的启发是保存可检查的摄影方法：描述输入、给出条件判断、生成适用描述、检验结果。原文案例不是本产品的实测证据，不直接复制为商用模板。

## 资产之间的关系

| 对象 | 保存什么 | 示例 | 如何复用 |
|---|---|---|---|
| 人物 | 身份描述、参考图及版本 | 数字模特 A | 换场景、姿态仍引用身份 |
| 摄影技能 | 完成一种创作任务的方法、条件与检查 | 机位规划、眼神突出、完整造型展示 | 对不同人物与风格执行 |
| 风格档案 | 审美偏好、默认值与技能版本引用 | 克制自然光摄影师 | 选择风格时载入偏好与相关技能 |
| 工作流模板 | 技能在哪一步使用、先后关系与产物 | 环境人像流程 | 复用组织方式，允许回到步骤调整 |
| 拍摄方案 | 本次人物、技能参数、风格与人工调整 | 模特 A 的窗边近景 | 复制为另一场拍摄 |
| 执行记录 | 技能版本、输入、建议、用户选择、最终文本与结果 | 机位规划 v1 的一次应用 | 追溯、对比与提炼新技能 |

一个虚拟摄影大师可以由风格偏好与多个技能组成。通用摄影技能能被不同大师共用；数字人物无需绑定某一大师。

## 每个摄影技能应包含的内容

| 部分 | 需要记录 | 产品作用 |
|---|---|---|
| 身份与检索 | 名称、稳定 ID、版本、分类、摘要、标签 | 找得到且历史可追溯 |
| 使用条件 | 适用任务、不适用情形、需要的素材或模型能力 | 推荐前判断能否应用 |
| 输入 | 必填 / 可选参数、选项、默认值、含义 | 自动形成可编辑表单 |
| 方法 | 按任务目标推导设置的说明与步骤 | 形成建议并解释原因 |
| 规则 | 条件、冲突等级、缺失提醒、解决方式 | 防止互相打架的配置 |
| 输出 | 生成的方案字段、提示词片段及检查清单 | 嵌入工作台并预览变化 |
| 示例与验证 | 原创示例、反例、测试条件、结果与人工评审 | 区分“写好了”与“效果已验证” |
| 来源与使用条件 | 来源链接、提炼说明、作者 / 录入者、授权信息 | 可追溯，不能把公开阅读等同于复制授权 |
| 版本与依赖 | 依赖技能版本、改动说明、替代版本 | 更新不污染历史作品 |

首版技能是声明式摄影知识与规则。外部文章里的指令不会自动成为可执行程序，也不会自动触发生图或上传。涉及脚本、插件安装和任意工具执行的技能属于独立后续范围。

## 完整示例：机位与视觉重点规划

以下为本项目原创产品示例，未经过生成效果验证。

- 技能 ID：camera-intent；版本：v1；分类：摄影 / 机位。
- 目标：让使用者明确观众先看什么，并将相机关系与画面取景转化为可检查的拍摄方案。
- 必填：画面主目标、拍摄目标锚点、取景范围。
- 可选：观察方位、相对锚点高度、镜头俯仰、主体占比、背景存在感、透视意图、距离 / 焦段。
- 默认值按目标提出建议，不能把一个默认机位用于所有任务。
- 输出：结构化机位方案、可编辑的生成描述、需检查的视觉重点。

示例输入：展示模特 A 的耳饰；锚点为耳部；侧向观察；取景为耳部至下颌；背景弱化。

技能建议：使用侧向局部近景，以耳饰细节为主体；保持耳部区域充分可见，背景不出现高反差元素。

原创输出示例：以人物耳侧的金属耳饰为视觉中心，采用侧向局部近景，耳部和下颌边缘进入画面；相机位于耳部参考高度，镜头接近水平，背景柔和简洁，保留金属表面细节。

检查：耳饰是否清楚进入画面？取景是否收紧？是否误生成全身？侧向观察是否成立？这是一份评审清单，不是自动通过结论。

### 规则示例

| 条件 | 等级 | 响应 |
|---|---|---|
| 缺少视觉重点或取景范围 | 输入错误 | 定位补充项，暂不能应用技能 |
| 目标为完整服装，但范围只到肩部 | 意图冲突 | 解释下装无法展示，给出“扩大取景 / 改目标”选项 |
| 目标为脸部细微表情，但主体占比很小 | 建议 | 提醒可能难以读到表情，允许保留环境叙事 |
| 想保留自然五官，又要求极近距离广角效果 | 建议 | 说明透视意图有张力，提供方案并允许有意保留 |
| 没选定锚点却使用相对高度 | 输入缺失 | 先补锚点，避免高度含义不明确 |
| 用户只写焦段数字 | 建议 | 补充可观察取景意图，不承诺模型物理执行精度 |

这些规则属于本产品的拟议行为。建议与硬错误分开，避免把摄影经验变成绝对禁令。

## 使用交互

1. 在专业流程的“摄影”步骤，选择“应用摄影技能”，按任务目标检索。
2. 选技能，查看适用范围、参数、来源与验证标签。
3. 填写参数，预览对方案字段与描述的影响；查看每条建议的原因。
4. 解决硬冲突，接受或保留软建议；显式应用到本次方案。
5. 由用户生成，结果与技能版本、参数、接受的建议一起保存。
6. 对结果标记有效 / 需调整；调整参数重试，或另存本次成功方法为技能草稿。

快捷入口：可选应用技能补充文本，也可以完全自由输入。应用前后文本可对比，不自动抹掉原始提示词。

作品详情：展示用了哪些技能、版本、参数与人工覆盖，支持复制旧版本方案或预览升级到新版本的差异。

## 创建技能的闭环

两种首版来源：手工新建；粘贴文章片段 / 提示词 / 成功方案并由 AI 辅助提炼。

提炼阶段分开显示来源事实、推断与新建议；保留来源位置，缺少必需知识的字段标为未知。AI 生成的规则先是草稿，用户校正后试用。

生命周期：草稿 → 待试用 → 已验证 / 需调整 → 归档。每次实质修改形成新版本；验证只对记录的技能版本、任务和模型条件有效，不能继承旧版“已验证”标签。

从成功作品保存技能时，用户选择哪些内容作为变量（人物、服装等），哪些是方法规则；不把一次完整提示词连同固定人物误保存为通用技能。

文章 URL 导入若不可读取，提示粘贴内容；不猜测正文。自动网页抓取与公开技能市场不是首版必要能力。

## 组合规则

首版建议按已有步骤设置技能槽位：服化道、姿态、场景、摄影、结果检查，每个槽位只应用一个主要技能；先验证摄影槽位，其他槽位保留扩展方向。

- 人物身份字段默认受保护，风格或技能不能静默改写。
- 用户已填写字段不静默被覆盖，所有改变都先预览。
- 风格提供默认偏好；技能基于当前目标提出方法建议；用户决定最终值。
- 两个技能写入同一字段的不同值时显示冲突，不靠提示词排列顺序解决。
- 多步骤执行时展示前置依赖；依赖缺失或循环时不能应用整个配方。
- 首版不同时实现自由节点编排或自动长链重试。

原先“最多两个风格档案按维度取用”保持为风格组合细则；技能之间如何协作另用槽位与字段冲突规则，二者不能混为一个混合比例。

## 建议首版切片

以一个“机位与视觉重点规划”技能贯通：新建 / 提炼 → 编辑参数和规则 → 试用 → 应用人物拍摄 → 检查结果 → 保存版本与作品关系 → 再次复用。

配套最低资产管理：分类、标签、任务检索、来源、状态、版本、复制、归档。先做私人资产库；公开分享、交易、脚本执行、多模型自动适配属于后续候选，权限边界为个人私有工作区，仅 AI 虚构人物；允许生成素材发送给生图服务；仅可恢复归档。

扩展顺序建议：先验证机位技能，再加入服化道、姿态与光线方法，最后把多个技能组织为大师配方。首版是否增加完整多技能编排，留待评审，不自动扩大实现范围。

## 验收与验证

- 参数模板在不同人物上复用，技能定义不变。
- 缺失参数可定位，意图冲突可解释和修复，软建议可保留。
- 应用前显示字段与文本变化，不覆盖人物身份。
- 执行记录锁定版本，技能更新后旧作品来源仍可查。
- 由文章提炼的条目保持草稿并记录来源，未经效果测试不显示已验证。
- 至少两个人物、两种任务的重复试用，分别记录任务目标、画面达成与需调整原因；未执行前不报告通过。
