# Prompt 资产管理与预览方案

- Scope：INIT；PRD v4；状态：REVIEWING。
- 本轮原话：日常从很多社交平台搜集好的生图提示词，认为 Prompt 是宝贵资产，管理与预览是大问题，希望融入现有产品。
- 已有约束沿用：个人私有；首版仅生成人像与 AI 虚构人物；无真人照片上传、公开分享、模型训练或永久删除。
- 两项用户已选择规则：可以收藏多题材文本但仅人像可生成；外部示例只保留链接，自生成结果可作封面。该选择不等于最终确认完整 v4。

## 意图、用户任务与目标

当我在社交平台看到值得尝试的 Prompt，希望先快速收下，之后通过视觉效果找回、试用、调整，并保留自己真正好用的版本。价值来自“可找到、能理解、可追溯地复用”，收藏量不是成功指标。

从原话推导的摩擦，尚未做访谈：来源散落；只看文字难想起画面；作者晒图可能缺模型或参考图；修改后不知道哪版跑出了满意结果；收藏内容与作品文件脱节。

资产至少由原始文本、来源、适用条件、版本、关联结果和个人评价组成。原文先保存，整理和试用后做，避免收集时要求填写完整表单。

## 机会优先级与证据

E-009 为发起人本轮意图；E-010 Midjourney 官方管理页说明按 Prompt、参数等搜索作品；E-011 ComfyUI 官方示例体现模型、种子及工作流信息对结果的影响。后两项是能力背景，不证明本产品价值或所有模型都支持相同参数。

优先顺序：快速收集 → 无图也能识别 → 自己的效果关联 → 查找与复用 → 版本积累。AI 自动优化、浏览器插件、跨模型批量测试属于后续候选。

## 候选方案与取舍

| 方案                                   | 价值与摩擦                                                 | 取舍                                     |
| -------------------------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| 社交平台收藏 / 文档 + 文件夹           | 立即可用，人工维护文字与图的关联                           | 保留为对照，先用真实素材验证是否值得开发 |
| 只有文本 Prompt 收藏夹                 | 收集快，但视觉找回和效果依据仍缺失                         | 不足以完成本需求                         |
| 私有 Prompt 库 + 现有任务 / 作品复用   | 同时管理收藏与本人的试用结果，减少第二套生图系统           | 推荐首版                                 |
| 抓取各平台 + 外部图导入 + 自动批量跑图 | 收集和预览更自动，但引入权限、媒体来源、模型适配和持续费用 | 暂缓；图片导入须重新定义数据边界         |

## 商业与运营模型

先服务发起人个人创作，通过实际收藏找回与复用节省时间；暂无收费、公开市场或协作。新增存储和用户主动试用费用，复用现有任务和作品管理。开库、搜索、悬停、收藏、换封面均不自动生图，不产生隐式生成费用。不接入社交账号或自动登录抓取；链接失效不导致本地已保存原文丢失。

首版原文手动粘贴、来源手动记录；来源信息只是出处记录，不代表复制、图片使用或再分发条件已确认。不内置抓取的第三方 Prompt 包，不公开分发收藏。

## 角色、权限与核心对象生命周期

| 对象        | 保存什么                                                                                                  | 与已有资产的区别 / 关系                                    |
| ----------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Prompt 条目 | 标题、题材、标签、原文、来源链接 / 作者（可未知）、收藏时间、个人备注、已知模型与参考条件                 | 独立存在，不要求先建项目、人物或先生成                     |
| Prompt 版本 | 本版完整文本、可选负面提示词、已知参数说明、修改备注、上版关系                                            | 原始收藏版本保留；不同文本不覆盖旧版                       |
| 试用关联    | 指定 Prompt 版本、实际提交文本、目标服务 / 模型（未知明确）、实际支持参数与参考输入、任务及结果、个人评价 | 使用现有生成任务；失败、拒绝和未知也保留，不另建假成功记录 |
| 预览封面    | 用户挑选的本人结果、所属 Prompt 版本与试用条件                                                            | 是作品引用，不复制一套作品；归档作品不清除图与历史来源     |
| 摄影技能    | 方法、参数条件、规则与检查项                                                                              | 可由 Prompt 显式辅助提炼为独立待试用草稿；收藏不自动变技能 |
| 风格档案    | 光线、构图、色调等审美维度                                                                                | 首版不从 Prompt 自动推断或合并成风格档案                   |
| 拍摄方案    | 本次人物、造型、场景、摄影配置                                                                            | 专业流程仍保护身份、处理冲突；收藏文字不静默覆盖方案       |

Prompt 生命周期：待整理 → 可复用 → 可恢复归档；是否已试用为独立事实维度。可复用表示信息可使用，不是效果保证。试用评价为未评价 / 满意 / 待改进，绑定具体版本与结果；新版不继承旧版评价。首版不提供“全模型已验证”或公共评分。

权限完全继承个人工作区。归档条目默认隐藏且阻止从其新发起应用；历史任务仍可查看；恢复保持所有版本、封面和关联。不提供永久删除。

## 端到端用户旅程

日常：粘贴 Prompt + 可选来源 → 保存到待整理 → 补标题 / 题材 / 标签 → 日后搜索找回 → 查看原文与适用条件 → 载入快捷生成草稿 → 检查最终文本、输入与费用 → 显式试用 → 选择结果作本版本预览 → 评价 / 修改另存 → 下次复用。

反向：在作品详情“保存为 Prompt” → 保存实际提交文本与原作品引用 → 可继续编辑新版本。不把结构化方案压成文字后伪称能复现全部引用素材。

进阶：在条目详情选择“提炼为摄影技能” → 保留来源 Prompt 版本 → 人工校正参数、方法和条件 → 独立保存待试用技能 → 按原技能流程试用。首版仍只贯通机位与视觉重点技能槽位。

## 信息架构、页面入口与核心交互

新增一级入口“Prompt”，与项目、人物、摄影技能、摄影风格、作品并列；快捷生成常驻。产品页面建议为 Prompt 库、收集 / 编辑、条目详情（版本与试用）；正式路由、模块划分和高保真稿留给确认后的规划。

库支持卡片 / 紧凑列表切换；查询覆盖标题、原文、备注、标签和已知来源作者；筛选题材、来源平台、已知模型、未试用 / 有结果、收藏与归档。标题可根据首段生成可编辑建议，但首版不依赖外部 AI 服务。

卡片显示封面或无图摘要、标题、题材、模型信息（可未知）、结果所属版本、是否有本版本结果。待整理可直接保存原文；标签非必填。相同原文的重复收藏提示已存在，用户可转到已有条目追加来源或明确另存；不自动吞掉文本或合并近似改稿。相同链接可包含不同 Prompt，不能只按 URL 去重。

复用已有草稿前给“另建草稿”或确认替换，取消保留当前输入。收藏和查看原链接不自动将条目发送给生图或提炼服务。主按钮是“载入快捷生成”，不是打开卡片就执行生成。

## 预览设计：让画面可找回，让依据可判断

| 预览层次       | 内容                                                  | 能证明什么                       | 首版规则                                               |
| -------------- | ----------------------------------------------------- | -------------------------------- | ------------------------------------------------------ |
| 文本预览       | 原文摘录、题材、关键视觉描述、已知模型与备注          | 描述意图                         | 未试用或无图时使用，不能以 AI 生成装饰图冒充结果       |
| 外部示例       | 作者帖子的示例链接                                    | 只提供外部展示出处；可能缺条件   | 仅链接，不抓取 / 缓存 / 内嵌外部图，打开原站由用户决定 |
| 自己的结果预览 | 关联本人任务结果，可看全部候选 / 对比，选择一张作封面 | 指定版本在已记录条件下的一次结果 | 只在显式生成后出现；标注 Prompt 版本、模型与参考条件   |

“预览”默认是读取已有图和文本，不是实时生图。单张图不代表固定输出或跨模型效果。同一版本多次生成保留不同结果；首版不自动选“最好”或删除不满意结果。

新版没有试用图：默认显示无图摘要和“本版本未试用”；可在详情查看上版结果，若用户选择旧版结果作封面，必须始终标“来自旧版 vN”，不能当作新版预览依据。作者示例与本人的结果不共用“已试用”标签。

预览图加载失败只重试读取图片，不新建生成任务。封面对应作品归档后关联仍保留；新建关联只允许选择自己有权限、未归档的结果，历史图的归档状态可见。取消或换封面不删除作品。

## 功能规则、异常与恢复

- 空库：粘贴收集入口；无筛选匹配：清空筛选；无预览：文字摘要和主动试用入口。
- 保存失败：保留原文 / 来源 / 备注，重试保存；未保存编辑退出给提示，不伪称成功。
- 源链接失效：保留手动原文与作者记录，标链接不可用；本地阅读、复制不依赖源网站。
- 模型未知：可收藏、复制；试用前明确目标服务与能力限制，不能默认原模型兼容。
- 目标服务不支持负面词或参数：保留原始版本，列出未应用项及最终实际文本；用户决定适配稿。不静默丢弃或承诺语义等价转换。
- 首版人像之外：按用户选择可存文本，但禁用内置生成并说明范围；不得自动猜成风光生成模式。
- 非虚构人物要求：不能应用到首版生图；允许编辑为虚构人物描述，不导入真人参考。
- 失败 / 拒绝 / 未知：完全沿用 F-006；未知先核实，不自动再跑来“补预览”。
- 无权限 / 不存在：不读取他人原文或封面；返回本人库。
- 外部内容只当数据：Prompt 中的指令不触发脚本、抓取、账户操作或额外传输。

## 可用性、可访问性与适配目标

收集界面仅原文必填；无图不影响收藏和检索。长文本可展开、有复制与版本差异入口；卡片键盘可进入，状态有文本。桌面先做，窄屏至少可粘贴收集、找回与查看；不引入原生 App 或分享扩展。

## 完整蓝图、首版切片与后续范围

首版建议：手动收集、保留原文 / 来源、标签与检索、版本保存、无图摘要、自生成预览、显式复用与作品反向保存、可恢复归档，以及复用已有提炼机制生成技能草稿。

后续候选：外部 AI 示例图导入（需用户选择与来源规则）、移动分享扩展 / 浏览器插件、OCR、自动抓取、语义 / 以图检索、自动摘要、变量化模板与片段组合、跨模型适配、批量测试、Prompt 到风格档案提炼。自由脚本、公开市场与团队共享不在此次请求内。

## 指标、假设实验与扩大 / 修改 / 停止条件

先用 20–30 条发起人真实收藏建立人工索引，与现有收藏 / 文档 + 图片文件夹对照：找回指定视觉意图的成功率、耗时、无图条目的可识别性、收集表单完成率，以及找到后真正试用 / 复用的比例。规模为建议实验样本，不是用户已拥有条目数。

测试旧版本封面：让使用者指出图属于哪个版本、是否自己的结果、是否可能缺参考条件；误解即调整标签。记录试用到满意结果的全部成本；没有满意结果时不能计算平均满意图成本。暂停自动化扩张直到手动闭环证明比替代方式有用；若文字摘要找回不足，再评审外部图导入与视觉检索。

## 未知、依据与 PRD 功能关联

- 外部示例预览方式与多题材收藏：用户已分别选择“自生成结果作封面，外部示例只留链接”和“允许收藏多题材，仅人像可生成”；未扩大既有图片权限。
- 尚无真实收藏样本、访谈、复现效果或量化基线；研究 PARTIAL。
- F-013 / AC-013：收集与检索；F-014 / AC-014：预览和试用依据；F-015 / AC-015：版本、复用及转化。
- F-005、F-008–F-012 关联 Prompt 版本与实际提交记录；不改变保护人物身份、用户显式应用或仅一个技能的限制。
- 模型是产品对象与行为方案，不定义数据库、API 或技术选型；支付、团队和公共分享无本期角色，故不新增这些流程。
